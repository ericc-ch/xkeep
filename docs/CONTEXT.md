# Context

## Product

Local X bookmarks app. Intake is a JSON bookmark export. No paid X API. No browser extension in v1. The pile is bookmarks; the process is the daemon.

### Product intent (2026-09-07 UI grilling)

"Do not lose a bookmark" means preventing a valuable bookmark from becoming buried and forgotten in a very large collection. The primary guarantee is rediscovery, not merely durable storage. The audience is technical power users. Rediscovery is the primary job and organization is secondary. The app is a canvas; "library" is not a user-facing product term. The canvas keeps the current automatic semantic layout: related bookmarks sit near each other, with no manual placement. xkeep does not proactively recommend or resurface bookmarks; discovery comes from seeing, moving through, filtering, and searching the canvas. Interaction is Figma-like direct manipulation: select marks individually or with a marquee, extend/reduce the selection, open one mark for detail, and delete the selection. There is no Keep action, review state, queue, or resurfacing mode. The deletion flow offers an Open on X link for each selected post. After user-assisted unbookmarking and confirmation, xkeep permanently removes the local record; xkeep does not claim to automate the upstream action. Design for 5,000–25,000 bookmarks. The product may add carefully chosen storage and API capabilities beyond the current backend, but this is a buildable near-term product rather than an unconstrained long-term concept.

The camera is a real zoom (floor `0.05`, ceiling `64`). Below 100% cards shrink with the view so the pile stays visible. Above 100% cards keep a steady screen size while positions spread, so overlapping stacks open up. Marks stay cards with images at every zoom; they do not collapse into overview dots or hide their stills. They may overlap; hover and selection raise a mark above its neighbors. At readable zoom, marks use one adaptive card system: media bookmarks are image-dominant cards with a compact author/text footer, while text-only bookmarks are compact post cards. Both share one footprint and selection language. Opening one bookmark uses a stable right-side inspector for the complete post, media, quote, links, tags, Open on X, and Delete.

When marks overlap, a normal click selects the top mark and Cmd/Ctrl-click cycles through every mark under the pointer. Permanent deletion retains only a tombstone (`bookmarkId`, deletion timestamp) so importing an older dump cannot resurrect deliberately deleted content; the bookmark row, tags, embeddings, and owned media are removed.

Search and filters operate directly on the canvas: matches remain bright while nonmatches dim without disappearing or moving. One compact floating top bar contains search plus filter and cluster controls. Tags stay off marks by default and can be shown as an optional color overlay. K-means groups are likewise an optional "Color by cluster" overlay rather than a primary mode or destination.

Single selection immediately populates the right inspector. Multi-selection turns the inspector into Figma-like shared controls: count, common and mixed tag states, bulk tag edits, and Delete. Secondary actions such as Copy links and Export live in a menu. The user-assisted deletion dialog offers an Open on X link for one selected post at a time. After the user confirms the post was unbookmarked, xkeep permanently removes its local record and advances to the next selected item.

The canvas restores its last camera position and zoom on launch. The world grid is infinite: it redraws from the camera, with no finite square edge. An always-visible minimap shows the full semantic space; its blue viewport rect is clipped to the plate, and corners that touch the plate follow the plate radius. First-run intake is copy-paste of the export snippet: the empty canvas card puts Copy snippet front and center, with Import JSON and drop-anywhere as file fallbacks. Copy snippet stays in the app menu after the canvas has bookmarks. The app menu trigger is the `xkeep` wordmark plus a chevron, with a floating panel (8px gutter). Pending import and embedding work appears in a compact status pill at the top right, hidden when idle, and shifted left when the inspector is open. Import counts and errors sit on the empty-canvas card or in the app menu.

Visual direction follows the current **X/Twitter dark design language**: a near-black canvas and panels, thin charcoal dividers, off-white primary text, muted gray metadata, round avatars, compact sans-serif typography, outline icons, and restrained Twitter-blue accents. Do not use X branding (𝕏 mark, Chirp, or other trademarks). Keep xkeep's full-window canvas composition; do not copy X's feed columns, navigation, trends, or other product structure. The overall feel is a dense, precise professional canvas tool rather than a dashboard or social feed.

## Terms

| Term     | Meaning                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------- |
| bookmark | One saved X post. The only pile.                                                                  |
| tag      | Plain string label on a bookmark. No ids, no hierarchy.                                           |
| cluster  | Ephemeral query result over embeddings — not stored.                                              |
| canvas   | Primary spatial view at `/`, containing every bookmark as a mark. Not a sqlite entity.            |
| daemon   | Long-lived `xkeep` server process on loopback.                                                    |
| gem      | A bookmark with high future value that risks being buried and forgotten in the collection.        |
| theme    | Locked dark skin in `packages/web/src/theme.ts`. Pixi reads it. StyleX vars copy the CSS strings. |

## Dump

A bookmark has `id` (numeric snowflake), author/handle, text, timestamp, hashtags, urls, avatar, optional quoted tweet, and `media[]` of type `photo` | `video` | `gif`. Videos may include a `poster` URL. Import rejects path-like ids. Export JSON is `{ bookmarks }`. Console snippet template: `scripts/dump-bookmarks.js`. Paste on `x.com/i/history`. Asks how many to export (empty = all). X `connect-src` blocks `fetch` from that tab to loopback (CORS and Local Network Access do not override it). The web UI bundles that template and Copy snippet find-replaces the quoted default `ORIGIN` URL (`http://127.0.0.1:5337`) with `window.location.origin` so the popup hits the app the user has open. The empty canvas card is the first-run path: title, numbered steps (open `https://x.com/i/history`, open the browser console, paste and run), primary **Copy snippet**, secondary **Import JSON** (file picker; needed when drag-and-drop is unavailable), and a muted drop line. Success shows “Snippet copied.” above Copy snippet. The xkeep app menu lists **Copy snippet** then **Import JSON** whether the canvas is empty or not. Auto-import (ADR 0016): the snippet asks a count, `confirm("Import N to xkeep?")` (the click keeps the popup unblocked), `window.open`s `{origin}/import`, and `postMessage`s `{ bookmarks }` from `x.com` / `twitter.com`; the popup checks origin, decodes the dump, `POST`s `/api/imports` same-origin, and auto-closes on success. Download + drop stays as the fallback. Do not print the ~400-line script on the card.

## Media

`pbs.twimg.com` URLs need a browser User-Agent to download. Keep every photo, or one video/gif poster, not the mp4. Re-check the hostname after every redirect. Stay on `https` twimg hosts.

## Embed

Qwen3-VL-Embedding-2B via official llama.cpp Vulkan (`llama-server`, `--pooling last`, pinned media marker) at **256 image tokens**. One fused vector: tweet text + all stills. Store 2048-d. A drain fiber waits until llama is `ready`, then embeds rows with a null blob. Short GGUF files are deleted and fetched again. Hub GGUFs: PATH `hf` if present (`hf download` into `{cacheDir}/gguf/`); else HTTP. GitHub llama tarball is HTTP only.

## Locked (grilling)

- **Embed:** Qwen only. See `docs/adrs/0001-qwen-llamacpp-vulkan.md`.
- **Media:** download stills under the data media dir. Photos: every image. Video/gif: poster only, not the mp4. URLs stay in sqlite.
- **Surface:** one bin `xkeep`. `service` is process lifetime (`start|stop|restart|status|serve`). `api` is one curl-style command (`method path` or OpenAPI `operationId`, `--param`, `--data` / `@file`, `--header`). Discovers the daemon; does not spawn. Bare / `service start` / `restart` / foreground `serve`: ensure (or listen) then print the ready banner (art, pid, origin, `/api/`, `xkeep api` example). Open the origin with the cross-platform `open` package. Effect `HttpApi` (not RPC), OpenAPI, web UI on the same API + SSE. Loopback, no auth. See ADR 0010, 0014.
- **Paths:** `env-paths` (`xkeep`, no `-nodejs` suffix). Data: sqlite, `media/`. Cache: llama binary and GGUF. Log: `{logDir}/xkeep.log` (JSON, Effect `Logger.toFile`, append). Daemon only; `api` / status do not write it. See `docs/adrs/0002-env-paths.md`.
- **Weights:** Q4_K_M text + mmproj Q8_0. Store 2048-d vectors. See `docs/adrs/0003-gguf-and-dims.md`.
- **llama.cpp:** PATH `llama-server` if present, else fetch pinned official Vulkan build into cache (GitHub HTTP, not `hf`); spawn child; `--cache-ram 8192`. `-c` is total KV across `-np` slots (per request = `c / np`).
- **Hub fetch:** If `hf` is on PATH (resolved with `which`), use it for Hugging Face GGUF URLs. Parse repo/rev/file from the existing Hub URL constants (no duplicate names). One `hf download {repo} {missing files} --revision {rev} --local-dir {ggufDir}`. Inherit stdio. Binary name `hf` only. After download, min-size check; too small → delete → HTTP GET. Missing or failing `hf` also falls back to HTTP. No config key. `HF_HOME` is hf’s cache, not xkeep’s. GitHub URLs never go through `hf`.
- **Listen:** `127.0.0.1:5337`. HttpApi is prefixed `/api` (`/api/health`, `/api/imports`, `/api/search`). OpenAPI at `/api/openapi.json`. Scalar at `/api/docs`. Origin `/` serves the canvas UI.
- **AppConfig:** `Context.Service` with `make(overrides)`. HTTP listen comes from the service. GGUF URLs, dims, prompts, and `LLAMA_BUILD` stay module constants. See `docs/adrs/0006-appconfig-service.md`.
- **Tooling:** Nub (`nub install`, `nub run`, `nub` for `.ts`). Root `"workspaces": ["packages/*"]`. Nub's regex script selection concurrently runs `dev:server` + `dev:web`; there is no custom process supervisor. `nub.jsonc` enables the `development` export condition and errors on stale dependencies. Root `build` is topological: tsdown emits ESM, declarations, and source maps for server/CLI while Vite emits web `dist`. `start` is `prestart` `build` then the compiled CLI serves the static web build. `xkeep` runs the source CLI with no subcommand (ensure daemon, banner, open origin). Node 26 on this machine; no `.node-version` pin.
- **Verification:** `nub run check` runs typecheck, network-free Vitest, lint, format check, one production build, then native Playwright E2E. Playwright launches an installed Chromium-family executable (Helium on this host), serves the production web build with real HTTP/SSE/SQLite and deterministic test embeddings, uses a unique temporary data directory, and removes it in global teardown. The browser flow covers import/status, canvas navigation, search/filters/overlays, selection/tags/export, deletion/tombstones, and browser errors. The same gate smoke-tests the compiled CLI, executable shebang/mode, server package resolution to `dist`, and web artifact. `nub run test:integration:network` is the separate opt-in pbs.twimg.com media-download canary; live network is never in `check`. See ADR 0018.
- **Packages:** `@xkeep/server` (`layer` + `./schema` dump + `./schema-http` wire + `./api` HttpApi), `@xkeep/cli` (`xkeep` bin, `service.json`), `@xkeep/web` (Solid 1.9 canvas SPA). Server exports use TypeScript source under the `development` condition and built `dist` files by default; the CLI bin targets `dist/main.js`. See `docs/adrs/0004-nub-workspaces.md`, `0005`, `0010`, `0012`, `0014`, `0017`, `0018`.
- **Effect:** `4.0.0-rc.112`. `@effect/platform-node` and `@effect/sql-sqlite-node` match.
- **SQLite:** See `docs/adrs/0007-drizzle-effect-sqlite.md`. Drizzle `1.0.0-rc.4` + `@effect/sql-sqlite-node`. File is `{dataDir}/xkeep.sqlite`. `Bookmarks` is the Effect port over the bookmarks table (not a generic Database service). Tags share sqlite. `sqliteTable` as SQL shape, leak SQL errors, `EmbeddingDimsError` for dim mismatch. Kit generate + `migrate()` on boot. Upsert nulls the embedding blob when text/media/still change. Deletion removes the bookmark row and keeps `bookmarkId` plus `deletedAt` in `deleted_bookmarks`. Import skips those ids.
- **Server layout:** `db/` is sqlite (client, migrate on the shared layer, tables, `Bookmarks`, `Tags`). `embed/` is llama + drain. `http/` is api, handlers, server, wire schema. `lib/` is leftover one-offs (cluster, import, search, thumbs). Root is dump `schema.ts`, `config.ts`, `log.ts`, `bus.ts`. A folder exists only when two or more files change together, except `lib/`.
- **Config:** server-only JSON at `~/.config/xkeep/config.json`. Never auto-created. Keys optional: `listen.host`, `listen.port`, `paths.data`, `paths.cache`, `paths.log`, `llama.port`. Precedence: flags > file > env-paths defaults. No `XKEEP_*`. CLI reads no config.json: `--url`, else `service.json`, else the built-in default. A strict file schema rejects unknown keys; `decodeField` validates each merged scalar. `AppConfig.make` directly returns its inferred resolved snapshot. `AppConfig.layer` requires `FileSystem`. `ConfigError` on boot. See `docs/adrs/0008-config-file.md` and `docs/adrs/0009-config-schemas.md`.
- **Domain:** **Bookmark** (saved post) + **Tag** = plain string; join is `bookmark_tags(bookmarkId, tag)`, unique per bookmark, case-sensitive; no tag table or ids. `GET /api/tags` is names + counts; a tag exists only while linked. Rename (`PUT /api/tags/:tag`) is one bulk update. No `source`. **UMAP** `x`,`y` are written once per row on the drain (`umap-js`). Later rows `transform` into that space via an in-process fitted model (gone on restart). Already-placed rows are not rewritten (a full refit rotates the whole map). Identical embeddings share one 2d point so they stack. Not on import (no vectors yet). **Cluster** = read-only `ml-kmeans` k-means++ in 2048-d (`groupId`) over embeddings; response reuses cached `x`,`y`. Not a table. Cluster tag apply is the bulk route `POST /api/bookmarks/tags` `{ memberIds, tag }` (user-triggered; no auto-tag). Cluster skips unembedded (`skippedUnembedded`). See ADR 0011, 0014, 0015.
- **Realtime:** Bus after sqlite commits + `GET /api/events` SSE. Events: `bookmark.tagged` / `untagged` `{ id, tag }`, `bookmark.upserted` / `embedded` / `deleted` `{ ids }`, and `import.status` `{ status }`. No `tag.*` events (ADR 0015). No coarse `bookmarks.changed`. Cluster reads do not publish. Web: `client.events()` (`StreamSse`) + atoms. Tag events invalidate bookmarks and tags. Upsert, embed, and delete events invalidate bookmarks and health. Import status invalidates health. CLI does not subscribe. See ADR 0010, 0014, 0015, 0017.
- **Daemon:** Ensure on bare + `service start`/`restart` only. Spawn detached `service serve`. CLI writes `service.json` after listen config resolves. `api` discovers (`--url` else `service.json` else default) and fails if down. Healthy = HTTP 200 on `GET /api/health` with `status: ok`. See ADR 0010, 0012.
- **Intake:** `POST /api/imports` upserts sqlite and returns counts for imported, updated, tombstoned, pending-still, and pending-embedding rows. No on-disk export copy. Stills download on a daemon fiber. Second import while that fiber runs is `409`. Health `import` is `idle` | `running`. The dump snippet does not POST from `x.com` (CSP). See ADR 0013, 0016, 0017.
- **Canvas UI:** `/` is a full-window Solid + Pixi canvas. Pixi draws media and text cards from cached UMAP coordinates. Below 100% zoom, cards scale with the camera (`0.05`–`1`); above 100% they counter-scale so they stay readable while neighbors separate (`1`–`64`). There is no low-zoom overview. It owns click, Shift-click, marquee, overlap cycling, pan, zoom, camera persistence, spatial culling, lazy thumbnail rungs (still painted when zoomed out), the viewport-tiled infinite grid, and the minimap (viewport rect clipped to the plate, plate-corner strokes use `radius.md`). Solid owns search, dim-only filters, tag and cluster color overlays, zoom controls, the empty-canvas snippet card, import from the `xkeep ▾` app menu, the top-right status pill, and the fixed right inspector. Page UI uses owned Kobalte wrappers in `packages/web/src/ui/` styled with StyleX in the locked X/Twitter dark language. Color, radius, shadow, and glass tokens live in `src/theme.ts` for Pixi and are copied as StyleX vars in `tokens.stylex.ts` (ADR 0019, ADR 0020). Copy and other action feedback sits on the control (hint line, dialog); there is no corner toast. `reset.css` is `@layer reset`; StyleX `useCSSLayers.before` is `reset` so `button { color: inherit }` cannot beat StyleX color. No shadcn package, Tailwind, or CVA. Single selection fetches `GET /api/bookmarks/:id` for quote, links, tags, local stills, Open on X, and Delete. Multiple selection shows shared and mixed tags, bulk tag edits, deletion, and a More menu for link copy and JSON export. The deletion dialog offers an Open on X link for each post and waits for user confirmation before `POST /api/bookmark-deletions` removes the local row. Rows without cached `x`,`y` are not drawn. `GET /api/clusters?k=` runs only while the cluster overlay is on. `GET /api/media/:name` accepts basenames inside `mediaDir`. Drain writes 32/64/128/256 WebP thumbnail rungs. One Pixi app stays mounted while SSE invalidation feeds `map.sync`. `packages/web` uses Solid 1.9, Pixi 8, StyleX, `@kobalte/core`, TanStack Router 1.x (code-based routes in `src/routes/`), and `@effect/atom-solid` / `AtomHttpApi` over `@xkeep/server/api`. Canvas layout lives in `src/canvas/`; reusable Kobalte+StyleX controls live in `src/ui/`; the Pixi controller is `src/map/`. The pinned Effect RC does not route `AtomHttpApi.mutation` through top-level groups. Web mutations use `XkeepApi.runtime.fn` and call the top-level client methods directly. Server serves `packages/web/dist` at `/`. See ADR 0014, 0016, 0017, 0019, 0020.
